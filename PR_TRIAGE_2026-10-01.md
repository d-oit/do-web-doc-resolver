## Follow-up 2 — Automated Cleanup (BLOCKED on permissions)

`Automated Cleanup` has failed on every scheduled run since **2026-08-09**
(eight consecutive weeks), in its first step, `Detect Unused Files`.

Root cause is a `set -e` trap. GitHub runs `run:` blocks with `bash -e`, and
`((skipped_count++))` evaluates to the *pre*-increment value, so at zero it
returns exit status 1 and `-e` aborts the script. `.cleanup-ignore` lists
`scripts/pre-commit-hook.sh`, which matches a file in the `scripts/*.sh` glob,
so the branch always fires. Because the step redirects its output into
`GITHUB_STEP_SUMMARY`, the abort produced no stdout — hence the bare exit code.

Fix:

```diff
-                  ((skipped_count++))
+                  skipped_count=$((skipped_count + 1))
```

Verified by extracting the real `run:` block and executing it under `bash -e`
with `GITHUB_STEP_SUMMARY`/`GITHUB_OUTPUT` set: before → exit 1, summary
truncated, empty outputs; after → exit 0, summary reports the skipped count.
The next step (`Check file ages via git history`) exits 0, and `actionlint`
passes over all workflows. This is the only occurrence of the pattern here.

**Blocker:** the GitHub App token has no `workflows` permission, so the change
cannot be pushed or written via the Contents API:

```text
! [remote rejected] refusing to allow a GitHub App to create or update
  workflow `.github/workflows/cleanup.yml` without `workflows` permission
HTTP 403 Resource not accessible by integration  (PUT /contents/...)
```

This blocks *any* `.github/workflows/**` change from this environment, not just
this one. A maintainer must apply the one-line diff, or grant the `workflows`
permission.
